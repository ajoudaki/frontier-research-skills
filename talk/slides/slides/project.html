Now the open project, which has problems a single question doesn't. You push in direction A, solve a step or three, and find it's a dead end, so you go back and try B, then C. That takes a lot of exploration, and exploration needs independence, because bias creates correlation: an agent that sees a failed attempt either keeps chasing the same idea, or copies the same approach and fails the same way. So each thrust lives in its own isolated study, running the one-question pair inside, and my AGENTS.md keeps every agent in its own study. But pure independence means never building on anything. organize-research-project strikes the balance with an established core of theory and code, reached only through the promotion gate: an independent audit, integration with the shared notation, tests and interfaces, and my approval. The gate also keeps out results that are true but worthless, or correct but unusable. What passes is heavily verified, so new studies can build on it, and it's worth my time to read. And when the project becomes a paper, review-ai-paper audits it cold: a fresh reviewer gets the finished paper, not its history, and its findings can start the next round.
