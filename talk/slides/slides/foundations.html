So that's the strategy. But it's easier said than done. Do we need smarter models? Surprisingly, no: the capability is already there. What's missing is the workflow around it. The conceptual force behind all of it is many agents. Not because they're faster: you pay for the tokens either way. A single thread accumulates everything: every dead end, every earlier claim, every sentiment. Once it makes an early mistake, everything after it is anchored to it, and telling it to be unbiased can't undo that. Separate agents start clean, especially if you isolate them and decide mechanically what they see. Run four, prompted for diversity. The first misses the flaw. So does the second. And the third. The fourth catches it. One catch is all you need: it's asking ten people instead of one person ten times. You can ask the main thread to start agents directly; what makes it practical are three basic foundations. Context: a coding agent, not a chat, on one always-on workstation. Then the theory, the LaTeX, the code, the results and the figures are all in reach. Agents work overnight, and even if you dispatch jobs elsewhere, the results come back. Persistence: everything under version control, and everything in the same place, theory included. Every snapshot holds the theory, the code, the audits and the paper together, so when an agent's refactor goes wrong, or you change your mind, you roll all of it back. And reuse. A project is just a folder with a file every agent in it reads, so the project's rules load by default. Prompts you type again and again become skills, which load by name or when a task matches them, and they're plain files, so they move with you to another model.
