04 · The basics

Agents, skills, and where they run

A coding agent, not a chat

Codex or Claude Code runs inside your repo. Papers, code and results are already in context.

One always-on machine

Connect from anywhere. Everything lives in one place, and agents work overnight.

Subagents

Fresh agents with a clean context. Each does one job and reports back: the key to checking results.

Skills

A folder with a SKILL.md. The agent sees only its description, and loads it when a task needs it or you name it.

AGENTS.md / CLAUDE.md

Project rules, read at the start of every session: AGENTS.md for Codex, CLAUDE.md for Claude Code.

Routing

A skill links reference files that open only when needed: of ten long papers, just the one it needs.

Some of these I didn't know existed until recently. One: leave the chat window. A coding agent like Codex or Claude Code runs inside your repo, so your papers, code and results are already in context. Two: run it on an always-on workstation you connect to from anywhere. Everything lives in one place, and the agents can work overnight. Then the pieces you configure. A skill is a folder with a SKILL.md file: the agent sees only its short description, and loads the full instructions when a task needs them, or when you name it. AGENTS.md, or CLAUDE.md for Claude Code, holds the project's rules and is read at the start of every session, so keep it short. Routing: a skill can link reference files that open only when needed, so out of ten long papers, the agent loads only the one it needs. And subagents: the main agent can spawn fresh agents with a clean context, which do one job and report back. Those turn out to be the key to checking results.
