So now we know how to run organize-research-project: we make the thrusts, formulate them, solve them, understand them, and promote what's true and relevant into the established core. But is that a scientific result? Not yet. Some results matter more than others, and a paper is judged on more than truth: novelty, significance, the literature. So we carve out the high-value part, and that needs a different kind of audit. review-paper reads the full submission, code included. It lifts out the three to five claims that matter most, into a ledger. Then it checks each one against its evidence. It re-derives the key proofs: here, the key lemma's proof fails. It retrieves the cited papers and checks that each citation is used correctly: one holds, and one source can't be verified. It audits the code: these baselines are unfair. It rates how plausible each conclusion is separately from how sound its argument is. Each flaw gets a severity: fatal, major or minor. And a fatal flaw cascades to every claim that depends on it: the main theorem falls with the lemma. The verdict says whether the central message stands, and the confidence reflects only what was actually checked. And its findings can start the next round of the project.
